# myblogweb 项目约定

## 项目定位

从零搭建个人博客。根目录 `D:\file\myblogweb`（2026-09-19 时为空目录，全新起步）。

## 文档体系（2026-09-19 确立）

`搭建设计和过程/` 存放全部设计与过程文档，**不参与网站运行**。三个子文件夹：

### 文件改动记录/CHANGELOG.md

- **每次改动文件后必须立刻追加一条**，AI 主动执行，不等用户吩咐
- 格式：按日期分组 + 表格，**倒序**（最新在最上）
- 列：`时间 | 类型 | 涉及文件 | 改了什么 | 为什么`
- 类型固定 5 个词：新增 / 修改 / 删除 / 重构 / 样式
- **粒度：一次操作 = 一行**，哪怕涉及多个文件也只写一行

### bug修复记录/BUGLOG.md

- 用户汇报 bug 或 AI 发现 bug 后自动记录
- 一个 bug 一张卡片，编号 `BUG-001` 起递增
- 字段：发现时间 / 现象 / 复现步骤 / 报错信息 / 定位过程 / 根因 / 修复 / 涉及文件 / 验证 / 反思 / 状态
- **根因与反思必须分开写**（根因 = 这次为什么错，反思 = 下次怎么不错）

### bug修复记录/经验教训.md

- 只放跨 bug 的通用规律；单个 bug 的反思留在 BUGLOG 卡片内
- 判断标准：一句话能说清、且以后还可能再犯，才写进来

### 设计方案/

内含：需求与目标 / 技术选型 / 架构设计 / 目录与命名规范 / 设计决策记录（ADR）。
ADR 重点记录**被否决的方案和否决理由**。除 ADR-001 外目前均为空模板。

## 已知限制

「自动记录」不是系统级文件监听，依赖 AI 在对话中主动落笔。用户离线自行改文件的情况不会被记录 —— 需要用户事后告知，或开工前扫描目录对比。

## 沟通约定

用户是编程新手：大白话、手把手步骤、表格对比、中文输出。技术方案先出对比表再拍板。
