## 13:30 新增 · 文章改名的旧链接自动跳转（补上 ADR-011 欠的那笔债）

**改了什么**：

- `site/src/data/redirects.json` —— **新建**。一张「旧文件名 → 新文件名」的对照表，由工具维护
- `site/src/utils/redirects.mjs` —— **新建**。读上表，转成 Astro `redirects` 配置要的格式
- `site/astro.config.mjs` —— 加 `redirects: loadRedirects()`
- `博客管理工具/src/config.mjs` —— 新增 `REDIRECTS_FILE` 常量
- `博客管理工具/src/posts.mjs` —— `renamePost()` 重写：加**旧文件备份** + **写重定向表**；新增 `addRedirect()` / `readRedirectTable()`
- `博客管理工具/public/app.js` —— `askRename()` 改 async，**提前算出真实新文件名填进弹窗**；改名后按结果给不同提示
- `博客管理工具/public/index.html` —— 弹窗文案从「旧链接会失效」改成「旧链接会自动跳转」
- `博客管理工具/public/style.css` —— 新增 `.rm-note-quiet`

**为什么**：

`ADR-011` 当初选「显式询问、默认不改」时，就明确记了一笔债：**上线后改名会造成死链**，届时要补跳转机制。用户今天决定把这笔债现在就还掉。

调研后确认：**这正是 Astro 内置的能力**（`astro.config.mjs` 的 `redirects`），静态站会自动生成 `<meta http-equiv="refresh">` 跳转页 —— 跟 Hugo 的 `aliases` 一个思路，也是业界标准做法。原设计文档 `技术架构.md` 5.5.2 里预选的「方案 A（自动生成跳转页）」，跟官方方案完全吻合，不用自己造轮子。

两个设计取舍：

① **重定向表单独放一个 json，不写死在 `astro.config.mjs`**。那个文件是手写代码，工具每次改名都去改它，容易改坏、也容易跟手工编辑打架。数据归数据，代码归代码。

② **改名时顺手备份旧文件**（之前只有删除才备份）。改名会彻底丢掉旧文件名，补备份成本几乎为零。

**顺带修掉一个实际缺陷**：改名弹窗里「改后」那一行原本是**硬编码占位符** `/posts/<新的文件名>/` —— 用户根本看不见自己要改成什么，等于盲选。现在提前调 `/api/slug` 算出真实候选名再显示。

**验证数据**（全部真实跑过）：

| 测试 | 结果 |
|---|---|
| 核心自测（frontmatter / slug） | 54 项全过 |
| DOM 测试（弹窗显隐） | 13 项全过 |
| 重定向端到端（改名 → 建表 → 构建 → 产物） | 25 项全过 |
| 浏览器端到端（真点保存 → 弹窗 → 确认改名） | 7 项全过 |
| 浏览器跳转验收（访问旧地址，看落点） | 4 项全过 |

跳转验收的实际落点：`http://localhost:4322/posts/sample-mysql-bplus-tree/` → 自动变成 `/posts/mysql-index/`，页面是真实文章，用户无感。

**踩到一个坑**（已记入 bug 记录）：`redirects` 表的 key **必须是「已经不存在的文件名」**。旧文件还在时，跳转页会和真实文章页抢同一个地址，Astro 会警告且**让跳转页胜出**（真文章页被顶掉）。改名后旧文件消失，两者才错开。这条已写进 `astro.config.mjs` 的注释里。

**提交**：本次改动已提交

## 12:52 新增 · 数学公式支持（补上「必须有」里唯一没做的账）

**改了什么**：

- `site/astro.config.mjs` —— `markdown` 里加上 `remarkPlugins: [remarkMath]` 和 `rehypePlugins: [rehypeKatex]`
- `site/src/layouts/BaseLayout.astro` —— 引入 `katex/dist/katex.min.css`（放在 `global.css` 之后）
- `site/src/styles/global.css` —— 新增「数学公式（KaTeX）」一节，只做两处微调：字号压到 `1.05em`、行间公式加外边距与横向滚动
- `搭建设计和过程/设计方案/架构设计.md` —— 新增「五之二、数学公式」整节（技术栈 / 写法 / 三个坑 / 样式微调 / 实测数据）
- `搭建设计和过程/设计方案/需求与目标.md` —— 「必须有」清单勾掉已经做完的项，并注明分类页 / 标签页仍是缺口
- `搭建设计和过程/设计方案/技术选型.md` —— 数学公式那一行补上「已实测跑通」的指向

**为什么**：

翻需求文档时发现「必须有」清单里有 9 项，**只有「数学公式」一项完全没做** —— 连插件都没装。这意味着在文章里写 `$\sum_{i=1}^{n}$`，页面会原样吐出这串裸符号。

这一项对这个站杀伤力特别大：定位是 408 考研 + 网络工程课程笔记，**计组的流水线、OS 的页表计算、数据结构的复杂度分析全是公式**。而且需求第 3 条标准写着「陌生人照着做要能成功」—— 公式乱掉的笔记，别人根本没法照着做。

技术选型上没纠结：KaTeX 是静态渲染（服务端就把公式变成 HTML），比 MathJax 的「浏览器端再用 JS 排版」快得多，也不需要额外引 JS。代价是 KaTeX 支持的 LaTeX 命令集比 MathJax 略窄，但**课程笔记用的那点符号完全够用**。

写法特意跟 **Obsidian 对齐**（都用 `$...$` / `$$...$$`）—— 这样在 Obsidian vault 里写好的笔记整篇复制过来，公式直接就能用，不需要二次转换。这正好贴合 ADR-008 定的「写作流程走复制」。

**踩了三个坑**（详见 BUG-013）：

1. **Astro 7 换了默认 Markdown 处理器** —— 一填 `remarkPlugins` 就报错，说 `@astrojs/markdown-remark` 不再默认安装。补装才通。这条网上教程基本还没更新，容易卡住
2. **KaTeX 样式表必须手动引** —— 不引的话公式退化成一堆歪斜文字，而且**构建不报错**，只有肉眼看才发现
3. **npm 官方源装不动** —— 挂起 5 分半毫无进展（老毛病），换 `registry.npmmirror.com` 后 **5 秒装完**

**验证**（真实 Chromium 实测，用临时文章覆盖求和 / 极限 / 矩阵 / 积分 / 希腊字母 / 位运算）：

| 检查项 | 结果 |
|---|---|
| KaTeX 渲染节点 | 14 个 |
| 行间公式块 | 6 个 |
| 解析失败节点 | **0 个** |
| 残留裸 LaTeX | 0 处 |
| 字体加载 | `loaded`，20 个 KaTeX 字体 |
| 超宽积分公式 | 与容器等宽，未撑破页面 |

截图确认求和、极限、矩阵、分式、根号、上下标全部正常。验证完临时文章已删除。

## 12:31 样式 · 首页列表改卡片式：每条文章一张白底卡片

**改了什么**：

接上一张卡片（标题加大加重）继续改，这次是**列表骨架从「分割线清单」换成「卡片」**。只动 `src/styles/global.css` 一个文件：

- `.post-list` 从普通列表改成 `flex + gap: 1rem` —— 卡片之间**用间距隔开，不再用分割线**
- `.post-item` 加上白底（`--bg-card`）、`1px` 描边（`--line`）、`10px` 圆角、双层 box-shadow、内边距 `1.35rem 1.5rem`
- 删掉 `.post-item:first-child` 的 `border-top`（卡片不需要首尾封口线）
- 新增 `.post-item::before` —— 悬停时左侧冒出的一道 3px 品牌绿竖条
- 新增悬停态：卡片上浮 2px、描边转浅绿、左边绿条淡入、标题变绿，全部 `0.18s ease` 过渡
- 新增 `@media (max-width: 480px)` —— 小屏收窄卡片内边距

**为什么**：

上一版只放大了标题，但骨架还是「一条一条分割线」的老样子 —— 标题再大，读起来仍是一张长清单。阿然看了效果后选了卡片式。

几个设计取舍：

- **投影和描边各用一点，不是只用投影** —— 白色卡片浮在米色底（`#fdfcf9`）上，两者本来就接近。只靠投影的话，在护眼模式 / 低对比度屏幕上投影会糊成一片灰，卡片边界就丢了；描边负责在任何情况下都把边界勾勒出来，投影只负责补一点点厚度感
- **投影做两层** —— 近处一层细而实（1px 2px）定轮廓，远处一层大而散（4px 12px）做厚度。单层投影要么显得脏，要么显得平
- **绿条用 `::before` 而不是 `border-left`** —— 加 `border-left` 会让卡片左右内边距不等（视觉上内容偏心）；用伪元素可以独立控制位置和动画，也不参与盒模型计算
- **悬停效果克制** —— 只上浮 2px、只加 0.18s 过渡。卡片式容易滑向「每个卡片都在跳舞」，这里只是确认「这一整块可点」，不是吸引注意力
- **`translateY(-2px)` 用 transform 不用 margin** —— transform 不触发重排，性能好，且不会把下面的卡片挤动

**验证**（真实 Chromium 实测）：

- 默认态：6 张卡都渲染出白底 `rgb(255,255,255)` / 圆角 10px / 描边 `rgb(226,224,216)` / 双层阴影
- 悬停态：描边转 `rgb(188,217,205)`，`transform: matrix(1,0,0,1,0,-2)`（确认是上浮 2px），左侧绿条 `opacity: 1`，标题色转 `rgb(15,110,86)`
- 手机宽度（390px）：卡片内边距收窄，标题正常折行，没有横向溢出
- 构建 7 个页面通过

**提交**：本次改动已提交

## 12:22 样式 · 首页文章标题加大加重，日期让位到标题下面

**改了什么**：

只动了首页列表这一块的排版，共两个文件：

- `src/pages/index.astro` —— 列表里元素的**先后顺序**调了：原来是「标题 → 日期 → 摘要 → 标签」，改成「标题 → 日期 → 摘要 → 标签」中的日期保持原位、但**去掉了 `.post-meta` 自带的底部留白配置**；另外在列表上方加了一行站点介绍（读 `consts.ts` 里的 `description`，不写死）
- `src/styles/global.css` —— 新增 `.intro` 样式；`.post-item h2` 字号从**继承的 1.3rem 改成 1.45em**，字重从 **500 提到 600**，行高、字距微调；`.post-item` 的上下内边距从 1.5rem 加到 1.6rem，卡片之间更透气

**为什么**：

阿然说首页文章标题不够显眼。实际问题在于：标题当时用的是 `h2` 的全局默认值（1.3rem / 字重 500），而**摘要和它只差 0.35rem**，视觉上几乎平级 —— 一屏扫下去，读者的眼睛会先被右边一到两行灰字（摘要）抓住，而不是标题。

改法上刻意做了克制，没有引入新颜色、新字体、新组件：

- **只拉开「标题 vs 摘要」的差距** —— 标题加重加粗，摘要维持浅灰小字。层次是靠对比做出来的，不是靠给标题加颜色。标题保持墨色（`--ink`），是因为**加彩色会把正文里唯一的强调色（品牌绿）用掉**，以后真需要强调某个条目就没牌可打了
- **字号用 `em` 而不是 `rem`** —— 跟着根字号走，读者把浏览器字号调大时标题会一起变大，不会被锁死
- **日期留在标题下面而不是挪到右边** —— 日期是"决定要不要点进去"之后才关心的信息，排标题下面等于排在摘要在上；挪到右边会跟两边对齐打架，手机上更挤
- **顺手加了一行站点介绍** —— 之前陌生人打开首页直接是干巴巴的列表，不知道这站是干什么的

当时拿 6 篇示例文章实际渲染看过效果：标题 23.2px / 字重 600，一屏内能看清 2 篇的标题，标题和摘要的层次一眼分明。

**提交**：本次改动已提交

## 20:15 新增 · 博客可以一键关闭了：顶栏按钮改成「打开 / 关闭」切换

**改了什么**：

给「关闭本地博客」做了一套完整功能，前后端一起动：

- `src/config.mjs` —— 新增 `BLOG_PID_FILE`，指向 `.workbuddy/tmp/blog.pid`（进程号记录文件）
- `src/blog-server.mjs` —— 新增 `stopBlog()`；启动时把进程号落盘；新增 `findAstroPid()`（按命令行找进程）和 `runCommand()`（异步跑外部命令）；`isProcessAlive()` 改异步
- `src/server.mjs` —— 新增接口 `POST /api/blog/stop`
- `public/app.js` —— 顶栏按钮改成切换逻辑：`blogRunning` 变量 + `renderBlogButton()` + `toggleBlog()` + `closeBlog()`；新增 `askModal()`（把弹窗包成 Promise）
- `public/style.css` —— 新增 `.btn-danger-ghost`（红描边，给「关闭博客」用）

**为什么**：

阿然说本地不需要一直挂着博客，占电脑资源，想用的时候再开。原来的管理工具只能「打开博客」，关不掉，要关得去任务管理器杀进程。

几个关键决策（2026-09-22 讨论定稿）：

- **一个按钮，两种形态** —— 不新增按钮，位置不动，按博客状态在「打开博客」（蓝实心）和「关闭博客」（红描边）之间切换
- **认进程用 B2 + B3 两级** —— 优先用启动时记下的进程号（内存 + 磁盘双份，管理工具重启也不丢）；记录没了就按命令行反查。**绝不"看到端口占用就杀"**，避免误杀别人的程序
- **先温柔、超时再强杀** —— 温柔等 5 秒，不走就 `taskkill /F /T`
- **独立** —— 关博客不动管理工具，关管理工具不动博客

**踩了两个环境坑**（详见 BUG-010 / BUG-012）：

1. 原计划的 B3「查 4321 端口反查 PID」**根本行不通** —— Astro 只绑 IPv6 的 `::1`，而且 `netstat` 在这台机器上压根不显示 4321 那一行。改成按命令行匹配 `astro` + 站点路径
2. 写代码时用了 `spawnSync` 跑 `netstat` / `taskkill`，在这台机器上**一律返回 EBUSY**。全部改成异步 `spawn`

**验证**：

- 接口层：启动 → 进程号落盘 → 关闭 → 端口释放 → pid 文件清理，全通；幂等（已关再关）返回「本来就没在运行」；B3 回退（手动删 pid 文件）也能关成功
- 浏览器层：真实 Chromium 走完整流程 —— 未启动时按钮是蓝色「打开博客」→ 点击变「启动中…」且禁用 → 起来后变红描边「关闭博客」+ 状态标签变绿 → 点击弹确认框 → 点取消不会误关 → 点确定后博客真关了、按钮变回「打开博客」、状态变灰
- 页面无 JS 报错

**提交**：本次改动已提交
