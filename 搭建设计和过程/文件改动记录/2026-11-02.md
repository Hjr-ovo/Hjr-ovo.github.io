## 21:40 新增 · Callout 提示框适配 + 管家启动时顺带拉起博客

**改了什么**

1. **Obsidian Callout（`> [!NOTE]` 那套）在站点里能正常显示了**（`site/src/utils/remark-obsidian.mjs` + `global.css`）
   - 以前：`> [!NOTE]` 只是一段普通引用块，页面上原样露出 `[!NOTE]` 这串字符（用户导入《OCR识别》里的 5 处全是这样）。
   - 现在：转成 `<blockquote class="callout callout-note">` + 一行标题（内联 SVG 图标 + 类型名），
     写法与 Obsidian 完全一致，包括 `> [!WARNING] 自定义标题`。
   - 支持 13 类（note / abstract / info / todo / tip / success / question / warning / failure / danger / bug / example / quote），
     别名一并收（`hint`→tip、`caution`→warning、`error`→danger…）。**不认识的类型原样保留**，不乱猜。
   - 颜色只靠一个 `--tone` 变量派生（`color-mix` 出底色和描边），深色模式 3 条通用规则搞定，不给 13 类各写一遍。
2. **`文章管家.bat` 双击时顺带启动博客预览**（新开一个最小化窗口跑 `npm run dev`）
   - 先查 4321 端口，已在跑就复用，不会起第二个 dev server 抢端口。
   - `site\node_modules` 不存在时跳过并提示，不影响管家本身。
   - 一个 cmd 窗口塞不下两个长进程，所以必须另开窗口；关管家窗口不回影响博客窗口。

**为什么**

- 用户从 Obsidian 直接复制笔记进站点，Callout 是最常用的一种块；让它"看得懂但不生效"等于每篇文章都要手改。
- 之前「写文章 → 预览」要双击两个文件（`预览.bat` 和 `文章管家.bat`），多一步且容易忘。

**踩到的坑（都已写进注释）**

- ⚠️ **括号块里不要放中文 `echo`**：65001 代码页下 cmd 按字节算行，行尾多字节字符会溢到下一行，
  导致下一行被当命令执行（干跑时报 `'需要的话先在' is not recognized`）。改用 `goto` 标签结构。
  这是 BUG-008「REM 中文吞前缀」的同类问题。
- ⚠️ **改了 remark 插件后 dev 不会自动生效**：Astro 把 Markdown 编译结果缓存住了，
  热更新只重跑旧模块。表现为「构建产物里 5 个 callout 全对，dev 里一个都没有」。
  解决：停 dev → 删 `site/.astro`（必要时连 `node_modules/.vite` 一起移走）→ 重启。
  **下次改 `utils/remark-*.mjs` 一律按这个来，别对着 dev 页面怀疑代码写错。**
