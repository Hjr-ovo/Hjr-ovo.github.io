## 14:30 样式 · 文章卡片整卡可点

用户反馈：卡片只有标题能点，想点哪儿都能进文章。

- 只改 `global.css` 一处（`site/src/styles/global.css`），模板一行没动。
- 做法是「拉伸链接」：`.post-item h2 a::after { position: absolute; inset: 0 }`。
  `::after` 的定位基准是最近的已定位祖先 —— 也就是早就 `position: relative` 的 `.post-item`，
  所以 `inset: 0` 正好等于卡片外框（含内边距），摘要、日期、空白处全在热区里。
- 配套两条：
  - `.post-item { cursor: pointer }`，鼠标走到摘要/空白处也变手型，别让人以为只有标题能点。
  - `.post-item .tag { position: relative; z-index: 1 }` —— 热区是绝对定位，会盖住同为行内元素的标签链接，
    必须把分类/标签提到它上面，否则点标签会跳到文章而不是标签页。
- 改动顺带覆盖另外三个页面：分类页 `/categories/<分类>/`、标签页 `/tags/<标签>/`、
  搜索结果页（`search.astro` 里的 `li` 也是 `.post-item`）—— 同一套结构，一处规则全部生效。
- **为什么用 CSS 而不是给 `<li>` 挂 click 事件**：伪元素本质还是那个 `<a>`，
  Ctrl+点击开新标签、中键新标签、右键「在新标签页打开」都是浏览器原生行为；
  用 JS 自己 `location.href` 跳转这三样全丢。而且不劫持点击，摘要照常能框选复制
  （纯 CSS 的代价只是「拖选摘要文字再松手」会触发跳转，短摘要可以接受）。

**验证**：dev（localhost:4321）里用真实浏览器点了三个位置——
点摘要（300,303）→ `/posts/hash-table-basics/`；点分类胶囊「数据结构」（62,335）→
`/categories/数据结构/`；点卡片右侧空白（620,250）→ `/posts/hash-table-basics/`。三条都符合预期。

- 用户从没手动选过时，监听 `prefers-color-scheme` 变化跟着系统走；一旦点过按钮就以他的选择为准
  （这条在测试里验过：存了 `light` 而系统是深色，打开仍然是浅色）。
- 顺手补了 `color-scheme` 的坑：只靠 head 里的 `<meta name="color-scheme">` 会让原生控件
  （滚动条、input）跟**系统**配色走，深色系统 + 手动切白天时滚动条仍是深的。现在两边都写死。
  滚动条颜色也走变量（`--scroll-thumb`），用 `scrollbar-width: thin` + `scrollbar-color`，
  这里没写 `::-webkit-scrollbar` 那套，所以可以直接用。

**抽屉搜索**：

- 第二列顶部加 `<input type="search" id="drawerSearch">`，`input` 事件即时过滤（子串、忽略大小写）。
- 提示行会随状态变化：没搜时讲怎么拖；搜了以后变成「匹配 2 / 3 个标签」，让人知道筛掉了多少。
- 零命中时给独立空态「没有匹配「zzz」的标签」，而不是和「还没有标签」混用一句话。
- 切换「标签 ⇄ 分类」时自动清空搜索词（留着上一个关键词只会让人困惑），placeholder 跟着改。
- 打开抽屉时焦点直接落到搜索框。
- 搜索框里按 `Esc`：有词就先清词（`stopPropagation`，别让全局 Esc 把整列一起收了），没词才收列。
- `.drawer-list` 补了 `flex: 1; min-height: 0` —— 搜索框吃掉一块高度后，列表得自己吃掉剩余空间
  才滚得动；少了 `min-height: 0`，flex 子项默认的 `min-height: auto` 会把抽屉顶破。
