## 14:55 新增 · 分类与标签改「多选胶囊」，带一键清除

**改了什么**：`public/index.html` 把原来的分类输入框 + 标签建议列表换成两套同构的
选择器（`#cat-picker` / `#tag-picker`）：上方「已选」区（每个已选项一个胶囊 + × 移除 +
「清除全部」文字按钮），下方「候选」区（点一下加入已选，已选项置灰标记），
最下方一个输入框 + 「添加」按钮（手动输新名字，回车等同点击）。
`style.css` 删掉 tag-suggest 一套样式，新增 picker 全套；`app.js` 的选中态改为
`state.formCategories` / `state.formTags` 两个数组维护——**不再从输入框文本反解析**，
候选列表、徽章、保存都读这两个数组。保存时输入框里没提交的内容会自动并入，
`categories` 为空则拦下不让存。

**为什么**：用户原话「里面的标签可以选择多个，还有一键清除选择的标签按钮」。
分类侧同一批改成多选，是因为分类本身在这天变成了多值字段——两边交互必须一致，
否则「分类能多选但标签不能」或者反过来，都很别扭。

三个设计决定：
- **胶囊 × 移除 + 清除全部 + 点候选 toggle**：多选的三种减员方式齐了。
  「清除全部」做成文字按钮而不是胶囊，避免和真正的选项混淆（和昨天搜索范围的
  「一键清除 / 全选」同一思路）。
- **选中态用数组而不是输入框文本**：老 UI 是「输入框里拿逗号分隔的文本」，
  多选后无法表达「哪些是已选项」（要反解析还得处理引号、逗号），
  干脆数组单一事实源，输入框只负责「加新值」。
- **保存时自动并入未提交输入**：用户打完字没点添加就保存，内容不该丢。

**验证**：多分类专项测试 19 项全过（含前端拼装/解析/校验的模块层）；
界面交互待用户在浏览器里实际点一遍确认。

## 14:55 重构 · 后台工具适配多分类（读写、校验、统计、改名）

**改了什么**：`src/frontmatter.mjs` —— `REQUIRED_FIELDS` 的 `category` 改
`categories`；`buildFile` 写 `categories: [...]`（新增导出 `yamlArrayString`，
逐元素过 `yamlString`，带冒号/逗号/井号的分类名不会被 YAML 吃掉）；
`validate` 增加分类的数组/非空/去重校验。`src/posts.mjs` 列表回传 categories 数组。
`src/taxonomy.mjs` —— 统计按 categories 展开（一篇多分类在每个分类下各计一次）；
改名/合并时逐篇文章重写 categories：匹配项替换、其余保留、**合并后去重**
（一篇同时有甲和乙、把甲并进乙时，不能留下两个乙）。

**为什么**：站点 schema 这天改成 `categories: string[]`，工具写的文件必须匹配，
否则保存出来的文章 Astro 直接报错。合并去重是这轮新出现的场景——
单值分类时代不存在「一篇里两个名字撞一起」。

## 14:54 重构 · 站点支持一篇文章属于多个分类

**改了什么**：`content.config.ts` 的 `category: z.string()` 改
`categories: z.array(z.string()).min(1)`；7 篇存量文章用一次性脚本
（`.workbuddy/tmp/migrate-categories.mjs`，幂等、保留原行尾）从
`category: X` 迁到 `categories: [X]`。所有消费点适配：分类总览/详情页
（分组循环改为遍历每篇的 categories）、首页/归档页/文章页的分类胶囊、
关于页的分类计数（`flatMap` + `Set`）、搜索页的内联索引（PostMeta 类型 +
渲染循环）、`utils/related-posts.ts` 的评分（「是否同分类」布尔 → 「共同分类数 × 2」）。

**为什么**：用户原话「我希望一个文章可以在多个分类里面同时出现」。
比如「npm install 卡死」那篇既属于「开发工具」也属于「踩坑」——
单值分类逼着人二选一，或者复制一份文章放两个分类，都是歪路。

三个设计决定：
- **`min(1)` 而不是允许空数组**：分类是文章的必填属性（原 schema 就是必填），
  放行空数组只会把错误推到构建期后面。
- **相关文章评分从布尔改计数**：单值时代「同分类」是 yes/no；
  多值后「共同分类数」才是自然的亲疏度量，阈值逻辑不变（×2、取 3 篇）。
- **分类页一篇出现多次**：总览和详情都按「每篇的每个分类各出现一次」渲染，
  不做篇内去重展示层的特殊处理——分类页的使命就是「这个分类下有什么」。

**验证**：`astro build` 通过，36 页、6 个分类页全部正确生成；
多分类专项测试 19 项全过；分类改名/合并端到端测试 33 项全过
（含构建产物验证：旧分类地址生成跳转页、新地址是真实页面）。
