## 10:45 修改 · 远程改用 SSH，AI 恢复推送能力

**改了什么**：

- `.git/config` —— `origin` 由 `https://github.com/Hjr-ovo/myblogweb.git`
  改为 `git@github.com:Hjr-ovo/myblogweb.git`
- `搭建设计和过程/设计方案/版本控制约定.md` —— 远程地址更新为 SSH 地址；
  「远程仓库」一节补写「为什么用 SSH 而不是 HTTPS」对照表与验证方法
- 顺带完成此前积压的推送：`main`（强推，历史已重写）+ 两个备份分支
  `backup-before-rewrite` / `backup-en-latest`

**为什么**：

2026-09-20 起，所有 git 远程操作（`push` / `ls-remote`）都返回 `exit 128`，
且错误信息被环境吞掉。当时的判断是「网络不通 / 需要图形界面授权」，
只能把推送这一步交给用户手动执行。

2026-09-21 用户提出「能不能用 ssh 来推送」，实测确认：

1. 本机 `~/.ssh/id_ed25519` 已存在，且公钥已注册在 GitHub 账号上
2. `ssh -T git@github.com` 返回 `Hi Hjr-ovo! You've successfully authenticated`
3. 把 remote 切成 SSH 地址后，`ls-remote` 与 `push` **全部一次成功**

**根因**：HTTPS 方式依赖 **Git Credential Manager**，认证时要弹**图形登录窗口**。
AI 在非交互环境里跑 git 时窗口弹不出来 → 请求卡住后失败，错误还被环境吞掉，
表现得很像「网络不通」。SSH 走密钥认证、**不需要任何弹窗**，直接绕开了这个限制。

**提交**：本次改动已提交
