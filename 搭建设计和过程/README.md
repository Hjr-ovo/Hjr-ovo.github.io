# 搭建设计和过程

博客项目（myblogweb）的全部设计文档与过程记录。

> 这个文件夹**不参与网站运行**，纯文档。删掉它网站照样跑。

## 索引

| 文件夹 | 作用 | 主文件 |
|---|---|---|
| `设计方案/` | 项目定下来的所有技术、架构决定 | 见文件夹内各文件 |
| `文件改动记录/` | 每次改动后追加一条 | `CHANGELOG.md` |
| `bug修复记录/` | 每个 bug 一张卡片，含反思 | `BUGLOG.md` + `经验教训.md` |

另外，**仓库根目录的 `Git` 也在承担记录职责**，规则见 `设计方案/版本控制约定.md`。

## 记录规则

**文件改动记录**

- 一次操作 = 一行（哪怕动了 3 个文件，也合成一行）
- 倒序排列，最新的在最上面
- 类型只用 5 个词：新增 / 修改 / 删除 / 重构 / 样式

**bug 修复记录**

- 一个 bug 一张卡片，编号 `BUG-001` 起递增
- **根因** = 这次为什么错；**反思** = 下次怎么不错。两者分开写
- 只有「多个 bug 反复踩同一个坑」才提升成通用规律，写进 `经验教训.md`

**设计方案**

- 定了的事写进去，**被否决的方案和否决理由也要写**（半年后你会需要它）

**版本控制（Git）**

- Git 记「事实」：哪些文件、哪些行变了 —— 工具自动生成，不会漏
- CHANGELOG 记「意图」：为什么改 —— 需要人来总结
- 两者用提交号互相索引，可双向查询
- 提交信息格式 `类型: 描述`，类型与 CHANGELOG 一致
