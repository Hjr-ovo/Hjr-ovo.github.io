## 〇、调研之后，先记住三条

| # | 结论 | 影响 |
|---|---|---|
| 1 | 「在网站里管理文章」这条路对静态站是**堵死的**：GitHub Pages 上跑不了 Node 服务，hexo-admin 官方也这么说 | 后台永远只能在你自己的电脑上跑，不要留「上线后网页改」的幻想 |
| 2 | 单人项目的正确形态是「**本地服务 + 直接读写磁盘**」，和 hexo-admin 同构 | 不做登录、不做 OAuth、不连 GitHub API —— 这反而省掉了这类工具最大的失败点 |
| 3 | 每月发文 1–2 篇的人，要优化的是**单篇成本**，不是吞吐量 | 范围砍到「入库 + 列表 + 编辑」，体检/改名/合并全部后置（见文末附录第 8 条） |

## 一、先定调：这工具到底该管什么

### 1.1 上次失败的真实原因

删除时逐项核查过：四类功能里**真正在用的只有「双击启停 dev」**。

| 上次做的 | 实际使用情况 |
|---|---|
| 在线编辑正文 | ❌ 从来没用过 —— 正文走 Obsidian（ADR-008） |
| 分类标签管理界面 | ❌ 没用过 —— 手写一行 frontmatter 更快 |
| 改名 + 重定向 | ❌ 没用过 —— 只有 1 篇文章，改名的需求还没出现 |
| 一键启停 dev | ✅ **唯一每天都在用的** |
| 图片上传、主题切换、统计面板 | ❌ 完全没碰过 |

**失败原因不是「做得不好用」，是「功能比真实需求多太多」**：5600 行里约 95% 是摆设，
而且每多一块功能，就多一块要维护、会出错、会分散注意力的东西。

### 1.2 构建层已经替工具干掉了三件事

2026-10-31 上线的 `remark-obsidian.mjs` 把格式转换搬到了构建阶段（现在已提交、跑在线上）：

| 原先以为要手工做的 | 现在谁做 |
|---|---|
| `date` → `pubDate`、`explain` → `description` | ✅ 构建层字段别名（`content.config.ts` 的 `z.preprocess`） |
| 正文 `#` 章节整体降一级 | ✅ 构建层 `remarkObsidian` |
| `==高亮==` → `<mark>` | ✅ 构建层 `remarkObsidian` |
| 文件名中文 → 英文 kebab-case | ❌ 没人做，**只能工具或手工** |
| 归类（分类必填、标签去重） | ❌ 没人做，**只能工具或手工** |

构建层做的还比工具好：转换只发生在内存 AST 里，`.md` 永远是 Obsidian 原样，
作者不用维护「两种写法」。所以**工具绝不能再去改正文标记** —— 那会重新制造两份写法。

### 1.3 于是只剩三块

| # | 功能 | 频率 | 解决什么 | 上次为什么失败 | 这次凭什么成立 |
|---|---|---|---|---|---|
| 1 | **入库** | 每篇 1 次 | 起英文名（决定 URL）、归分类、写进 `posts/` | 上次把「格式转换」也塞进来，结果和 Obsidian 打架 | 只做构建层管不了的「起名 + 归类」，正文一个字不碰 |
| 2 | **管理** | 偶尔 | 改元数据、开草稿、改名、删除 | 上次侧重点是在线写正文 | 只改 frontmatter 和建议性修改，不碰正文结构 |
| 3 | **体检** | 每篇入库 + 手动全站 | 把构建层「默默处理」和「处理不了」的地方摆到明面上 | 上次完全没有 | 构建层越多自动转换，越需要有人告诉你它干了什么 |

**一句话定位**：一个只服务一个人的本地文章管家，负责**构建层管不了的那些判断性、管理性动作**。
删掉这个文件夹，网站照常跑 —— 它是使用者，不是被使用者。

## 二、一条真实链路：从 Obsidian 写完到站点上线

把工具的每个按钮放回真实场景里，才知道哪些是必需的。

```text
① 在 Obsidian 写完（标题、正文、可能带 ==高亮==、可能用 # 当一级章节）
        ↓
② 导出 / 复制这篇 .md
        ↓
③ ★ 工具：拖进来 → 看到「这篇会发生什么」→ 定英文文件名 → 选分类标签 → 写入
        ↓
④ 工具自动切到站点预览（localhost:4321/posts/<文件名>/）看一眼
        ↓
⑤ 发现错别字 / 想改分类 / 想先压成草稿
        ↓
⑥ ★ 工具：列表里点「编辑」，改完保存，dev 热更新，刷新即见
        ↓
⑦ ★ 工具：体检跑一遍，确认没有「缺字段 / 标题跳级 / 重定向撞车」
        ↓
⑧ ★ 工具：看到「3 个文件已改动」→ 一键提交（可选，默认只提示）
        ↓
⑨ 手动 git push（或让工具代劳，见 4.9）
```

带 ★ 的五步就是工具的全部价值。第 ⑧ ⑨ 步是这次新增的想法（v1 草案没写），
因为「攒了 8 个提交没推」这件事刚刚真实发生过。

## 四、功能详细规格

### F1 文章列表

**目的**：打开工具 3 秒内知道「站里有什么、哪篇有问题」。

**界面**：

```text
┌──────────────────────────────────────────────────────────────────┐
│ 文章管家        站点 ● 运行中(localhost:4321)   3 篇 · 1 草稿 · 2 告警│
├──────────┬───────────────────────────────────────────────────────┤
│ ＋入库    │ 搜索 [            ]  分类[全部▾] 状态[全部▾] 排序[日期▾]│
│ 文章列表  │ ┌───────────────────────────────────────────────────┐ │
│ 体检      │ │ 哈希算法与哈希表：冲突、扩容和 O(1) 是怎么来的  ⚠2│ │
│ 设置      │ │ 2026-10-31 · 数据结构 · 4200 字 · 12 分钟 · /hash… │ │
│           │ │                        [编辑][改名][删除][打开]  │ │
│           │ └───────────────────────────────────────────────────┘ │
└──────────┴───────────────────────────────────────────────────────┘
```

**每行显示什么（都来自现算，不缓存）**：

| 列 | 来源 | 说明 |
|---|---|---|
| 标题 | frontmatter `title`，缺则取首个 h1 | 缺字段时标红 |
| 告警数 | F5 体检的单篇规则结果 | 0 时不显示徽标 |
| 日期 | `pubDate`，有 `updatedDate` 则旁边加「· 已更新」 | 与时区无关（直接读字符串） |
| 分类 / 标签 | frontmatter | 点击即筛选 |
| 字数 / 阅读时长 | 复用 `site/src/utils/reading-time.ts` 的算法 | 汉字 350/分、英文词 200/分、代码行 50/分 |
| 路径 | `/posts/<文件名>/` | 点击复制 |
| 状态 | `draft: true` 显示「草稿」灰标 | |

**交互**：

- 搜索：标题 + 标签 + 文件名，即时过滤（不打后端，全在前端筛）
- 排序：日期新→旧（默认）/ 标题 / 字数 / 告警数
- 点标题 → 进编辑页；点「打开」→ 浏览器新开站点对应 URL（dev 没开就提示先启动）

**异常**：

| 情况 | 表现 |
|---|---|
| `posts/` 空 | 显示空状态 + 「去入库」按钮 |
| 某篇 frontmatter 解析失败 | 该行标红并显示「无法解析：第 3 行缺少结束的 `---`」，不阻塞其他行 |
| dev 未运行 | 顶部站点状态变灰「未运行」，按钮提示「双击根目录 预览.bat」 |

**验收**：现有 1 篇文章正确显示；手动改名一个文件后刷新列表跟着变（证明每次现读磁盘）。

### F2 入库向导（核心，也是唯一"新造"的功能）

**目的**：把「Obsidian 稿子 → 站点文章」这条路上的所有手工判断，变成一次点选。

#### 4 步流程

```text
① 拖入文件（或点选择）
     ↓
② 诊断：只读不写，告诉你「这篇会发生什么」
     ↓
③ 起名 + 归类：文件名（= URL）、分类（必填）、标签（可空）
     ↓
④ 写入：先写临时文件再 rename → 成功则跳到站点预览
```

#### ② 诊断清单（工具最该说人话的地方）

拖进来的那一刻就把结果摊开，不用你自己去数：

| # | 诊断项 | 输出示例 | 严重度 | 为什么要说 |
|---|---|---|---|---|
| D1 | 标题来源 | 「从 `title` 取到：哈希算法与哈希表…」 | ℹ️ | 让你确认它认的是哪一行 |
| D2 | 必填字段 | 「缺 `description`，构建会失败」 | 🔴 | 别名只兜 `date`/`explain`，不兜缺字段 |
| D3 | 日期来源 | 「`pubDate` 未写，将用 `date: 2026-10-31`」 | ℹ️ | 别名生效了，你该知道 |
| D4 | h1 数量 | 「3 个 h1 → 构建时整体降一级」 | ℹ️ | 让你确认插件按预期工作 |
| D5 | 跳级标题 | 「`#` 后直接跟 `####`，降级后是 `#####`，**目录收不到**」 | 🟠 | **构建层救不了的角落** |
| D6 | 高亮对数 | 「5 处 `==` 会转高亮；代码块内 12 处已免疫」 | ℹ️ | 让你确信没误伤 `a == b` |
| D7 | 未配对 `==` | 「正文第 88 行有一个落单的 `==`，会原样露出」 | 🟡 | 插件不吞内容，但难看 |
| D8 | 图片链接 | 「6 张图，全部是 https 图床链接」/「1 张本地路径 `./img/a.png`，站点上会裂」 | 🟠 | 本地图片不会被打包进去 |
| D9 | 正文大小 | 「4200 字，9 个代码块，预计阅读 12 分钟」 | ℹ️ | 顺便给个手感 |
| D10 | 编码 / BOM | 「文件是 UTF-8 with BOM，将去掉 BOM」 | ℹ️ | BOM 会让 YAML 解析怪异地失败 |
| D11 | frontmatter 多余字段 | 「有 `aliases`、`cssclasses` 等 4 个 Obsidian 专用字段，会被忽略」 | ℹ️ | 免得你以为它们在生效 |
| D12 | 分类是否已存在 | 「`数据结构` 已有文章；`算法` 是新分类，会新建分类页」 | ℹ️ | 新分类会让左侧多一个入口 |

**诊断只预测，不改文件**。真实结果以站点渲染为准 —— 这条必须写进界面提示，
否则「工具说会的，站点没做」会变成信任崩塌的开始。

#### ③ 起名规则

| 规则 | 说明 |
|---|---|
| 生成方式 | 优先用 frontmatter 里已有的 `slug`；否则「中文标题 → 英文 kebab」，**查术语词表 + 记忆**：内置一份常用词（哈希→hash、线性探测→linear-probing、红黑树→red-black-tree…），每次确认过的对应关系写进 `site/src/data/slug-glossary.json`，下次直接用，越用越准 |
| 兜底 | 词表覆盖不到时**不硬编拼音**（`hsyfc` 这种名字比中文名更糟）：留空让人填，并给 3 个候选（`topic-1` / 取标题里的英文词 / 用日期 `2026-11-topic`） |
| 可改 | 永远可编辑，输入框旁实时显示 `/posts/<名字>/` 最终 URL |
| 校验 | 只允许 `a-z0-9-`，首尾不能是 `-`，长度 ≤ 60 |
| 撞名 | **拒绝，不自动加 `-1`**（否则两篇文章的关系就乱了），提示「已存在，换一个」并给出 3 个候选 |
| 中文名 | 允许但标黄警告：URL 会变成 `%E5%93%88…` 这种编码，分享出去难看（ADR-006） |

#### ③ 归类规则

| 字段 | 规则 |
|---|---|
| 分类 | **必填至少 1 个**，可多选。选项来自「现有文章里出现过的分类」去重 + 手填新分类 |
| 标签 | 可空。选项同上；**与分类完全重名的标签会提示去掉**（会让标签页和分类页重复收录） |
| 日期 | 默认今天；文件里有 `date`/`pubDate` 就用文件里的，可改 |
| 草稿 | 默认关闭；勾上则 `draft: true`，文章不进列表也不生成页面 |

#### ④ 写入规则

| 事项 | 做法 |
|---|---|
| 写入位置 | `site/src/content/posts/<文件名>.md` |
| frontmatter | 按规范顺序重排 7 个字段（新入库的文件本来就没有需要保护的注释），但 Obsidian 专有字段（`aliases`、`cssclasses` 等）**原样保留在末尾** |
| 正文 | **逐字节原样保留**（含 `==`、`#`、代码块、空行），一个字符都不动 |
| 原子性 | 先写 `<文件名>.md.tmp` 再 `rename`，中途失败不留半截文章 |
| 覆盖 | 同名已存在直接拒绝（与起名校验双保险） |
| 完成后 | 顶部提示「已写入，3 秒后在站点打开」+ 按钮直接跳转；同时提示 git 状态变了 |

**验收**：把 `tmp-obsidian-test.md` 这类带 `date`/`explain`/3 个 h1/两处 `==` 的文件拖进去，
诊断结果与实际渲染结果逐条相符；写入后正文与源文件 `diff` 为 0 行差异。

### F3 单篇编辑

**目的**：改元数据、改错别字、开关草稿。**不是**写文章的地方。

**界面**：上半是元数据表单，下半是正文纯文本域（等宽字体、行号可选）。

| 区域 | 内容 |
|---|---|
| 元数据 | 标题（单行）、描述（3 行）、日期（date 选择器）、分类（多选胶囊，可新增）、标签（同上）、草稿（开关） |
| 正文 | `<textarea>` 纯文本，等宽字体，Tab 键插入两个空格（不跳焦点） |
| 底部 | 「保存」「取消」；右上角显示「未保存改动」标记 + `Ctrl+S` 快捷键 |

**必须遵守的三条**：

1. **保存前重新读一次磁盘**。如果文件在工具外被改过（比如你用 Obsidian 又动了一下），
   弹出「磁盘上的版本比工具里的新，要覆盖吗 / 重新加载 / 看差异」，**绝不静默覆盖**。
2. **保存时做最小改动，不整份重写**。只替换真正被改的那几行（改标题就只动 `title:` 那一行），
   新增字段追加到末尾，其余字节 —— 注释、空行、字段顺序、引号风格 —— 一个都不碰。
   **解析成对象再序列化是禁止的**：那样每次保存都会把整个 frontmatter 重排一遍，
   git diff 变成一坨，等于失去了「看清楚改了什么」的能力。
   未知字段（`aliases`、`cssclasses` 之类）同样原样留着，不删。
3. **正文不做任何格式化**：不 trim、不补末尾换行、不转换全角半角。

**异常**：

| 情况 | 表现 |
|---|---|
| 文件名含中文 | 顶部黄条提示「这篇 URL 会被编码，建议改名」+ 一键跳 F6 |
| 保存失败（文件被占用 / 权限） | 保留编辑内容不清空，显示具体错误码 |
| 正文为空 | 允许保存（但体检会报 🟠「空文章」） |

**验收**：改一个标签保存 → dev 热更新后分类页/标签页跟着变；改正文里一个错字 →
其余字符逐字节不变（用 `git diff` 确认只有那一行）。

### F4 打开站点

**目的**：从工具直接跳到「这篇在网站上长什么样」。

| 行为 | 说明 |
|---|---|
| 检测 dev | 请求 `http://127.0.0.1:4321/`，2 秒超时 |
| 运行中 | 直接新窗口打开 `/posts/<文件名>/` |
| 未运行 | 按钮变成「启动预览」→ 执行根目录 `预览.bat`（**不自己起进程**，避免和 bat 抢端口） |

> 为什么交给 `预览.bat`：2026-10-30 已经做了一键启动，再实现一套进程管理就是重复造轮子，
> 而且要处理「已在运行就别起第二份」这类边界 —— bat 已经处理好了。

### F5 体检（v1 草案里叫「唯一能防止站点慢慢烂掉的功能」）

**目的**：构建层越自动，你越需要有人告诉你「它悄悄做了什么、哪里没兜住」。

**两个入口**：入库时自动对该篇跑一次；列表页「体检」跑全站。

#### 规则表

| ID | 规则 | 严重度 | 检测逻辑 | 可否一键修 |
|---|---|---|---|---|
| L1 | 缺必填字段 | 🔴 构建会失败 | 校验 `title`/`description`/`pubDate`/`categories` | 否（要人填） |
| L2 | 分类为空数组 | 🔴 | `categories.length === 0` | 否 |
| L3 | 文件名含中文或大写 | 🟠 URL 会编码 | `/^[a-z0-9-]+$/` 不匹配 | 否（改名要走 F6） |
| L4 | 重定向表 key 指向现存文件 | 🔴 会顶掉真文章 | `redirects.json` 的 key 是否在 `posts/` 里存在 | **是**（删除该条） |
| L5 | 重定向链没拉直 | 🟡 A→B、B→C | 遍历表找链 | **是**（A 直接指 C） |
| L6 | 标题跳级 | 🟠 降级后仍进不了目录 | 解析正文标题序列，检测 `h1→h3` 这类跳级 | 否（要人判断） |
| L7 | `==` 未配对 | 🟡 原样露出等号 | 统计非代码区的 `==` 数，奇数即告警 | 否 |
| L8 | 标签与分类重名 | 🟡 重复收录 | 两个数组取交集 | **是**（从标签里删） |
| L9 | 只有 1 篇文章的「孤儿分类」 | 🟡 可能拼错 | 分类计数 == 1 且不是本次新建 | 否 |
| L10 | 本地图片路径 | 🔴 **阻断入库** | 正文 `![](...)` 里非 http 的路径 | 否（要上传图床，或明确选「先这么放着」） |
| L11 | 正文为空 | 🟠 页面空白 | 去 frontmatter 后 trim 为空 | 否 |
| L12 | 描述过长 | 🟡 搜索结果被截断 | `description.length > 120` | 否 |

> **L1 / L2 的做法要改**：不要自研 schema 校验 —— 直接跑项目自己的 `astro check`
> （或 `astro build`）拿权威报错再解析，自研规则只补构建**管不到**的那些（L3–L12）。
> 构建器永远比我们手写的校验准确，而且 `content.config.ts` 一改它自动跟上。

**输出**：

```text
全站体检  2026-10-31 18:40   1 篇 · 4 条问题（2 红 2 黄）· 用时 12ms
┌──────────────────────────────────────────────────────────────┐
│ 🔴 L1  hash-table-basics.md   缺 description，构建会失败      │
│ 🟠 L3  my note.md             文件名含空格和中文              │ [改名]│
│ 🟡 L8  hash-table-basics.md   标签「数据结构」与分类重名      │ [修掉]│
└──────────────────────────────────────────────────────────────┘
```

**验收**：L1–L12 各造一个坏样例文件，全部能被检出且严重度正确；
「可一键修」的三条修完后再跑一遍归零；误报率 0（正确的文件跑不出问题）。

### F6 改名（= 换 URL，最危险的操作之一）

**目的**：文件名就是 URL（ADR-006），所以改名必须同时处理死链。

**流程**：

```text
点「改名」→ 输入新名（必须符合 kebab 规则）→ 撞名检查
     ↓
弹出确认框，写清楚代价：
   「旧地址 /posts/hash-table-basics/ 会 404。
     将自动在 redirects.json 里加一条 旧→新 的 308 跳转。
     标题不会跟着改（要改标题请去编辑页）。」
     ↓
[确认改名] → 写盘 + 追加重定向 + 提示
```

**规则**：

| 项 | 做法 |
|---|---|
| 是否跟随标题变 | **默认不跟随**，必须显式确认（ADR-011） |
| 重定向写入 | `site/src/data/redirects.json`，key = 旧名，value = `/posts/新名/` |
| 旧名仍是现存文件 | 拒绝改名并提示（否则会顶掉真文章，BUG-014） |
| 已有指向本文件的旧 key | 一并换成新目标（拉直，避免两跳） |
| dev 是否自动生效 | 是，但需刷新页面；提示「刷新后验证旧地址」 |

**验收**：改名后旧 URL 返回 308 并跳到新页；`redirects.json` 格式与手工添加一致；
连改两次名后旧 key 直接指向最终地址（不是链式两跳）。

### F7 删除 + 回收站

**目的**：唯一不可逆的操作，必须留退路。

| 步骤 | 做法 |
|---|---|
| 点删除 | 二次确认，把标题打出来让你确认删的是它（不是「确定吗？」这种废话） |
| 备份 | 复制到 `.workbuddy/tmp/deleted-posts/<时间戳>-<文件名>.md`，同时把它的重定向条目一起记下 |
| 删源 | 才删 `posts/` 里的文件 |
| 可恢复 | 列表页底部「回收站」列出备份，点「还原」写回 `posts/` 同名位置（撞名则问） |
| 保留期 | 不自动清（磁盘不值钱，误删才要命） |

**验收**：删掉再还原，文件内容逐字节一致；还原后站点页面恢复可访问。

### F8 分类与标签总览

**目的**：错别字分类（`数据结构` / `数据结构 ` / `数据结购`）会永久挂在站点上，得能收拾。

| 功能 | 说明 |
|---|---|
| 总览 | 每个分类/标签 + 文章数 + 最近使用日期 |
| 筛选 | 点一下即回到列表页并按它过滤 |
| 重命名 / 合并 | 把 `数据结购` 改成 `数据结构` = 批量改写所有文章的 frontmatter 数组，一次原子操作 |

**验收**：把 A 合并进 B 后，所有相关文章的 `categories` 里 A 全部变 B，且没有文章出现重复项。

### F11 git 状态面板（P2，本次新增的想法）

**为什么加**：2026-10-31 出现了「本地攒了 8 个提交没推」的真实情况 —— 这不是懒，
是「切到终端敲命令」这件事本身有摩擦力。

| 功能 | 做法 |
|---|---|
| 状态 | 跑 `git status --porcelain`，显示「N 个文件已改 / M 个提交未推送」 |
| 提交 | 输入一句话 → 执行 `git add -A && git commit -m "..."`，输出结果显示在面板里 |
| 推送 | 可选按钮，执行 `git push`；失败时把 stderr 原样贴出来（不吞错误） |
| 提交信息规范 | 文本框预填 `type: `，给出 5 个 type 的提示（新增/修改/删除/重构/样式对应 feat/fix/…，见 ADR-012） |
| 安全 | **不做 `git reset` / `checkout` 这类破坏性操作**，只做 add / commit / push |

> ⚠️ 这条要你拍板：工具代跑 git 会绕过我（AI）和你的双重检查。好处是推得出去，
> 坏处是「一次错误提交」也可能被推上去。默认**只读显示状态**，提交/推送按钮放在设置页里。

### F12 图床链接检查（P2）
