## 一、方案大类：静态 vs 动态

| 方案 | 需要什么 | 判断 |
|---|---|---|
| WordPress 这类**动态博客** | 服务器 + 数据库 + 后台管理，要运维、要防攻击 | ❌ 排除。违背已确认的「不做后台」「不自己运维」 |
| **自己写**前端 + 后端 | 前后端全部自己实现 | ❌ 排除。会让项目变成「一直在做站、零篇文章」，成功标准第 5 条直接挂掉 |
| **静态站点生成器（SSG）** | 只要会写 Markdown | ✅ **选定**。命中全部已确认需求 |
| 直接用知乎 / 掘金 / CSDN 等平台 | 什么都不用装 | ⚖️ 备选。最省事，但内容不归自己、样式不能改。用户目标是「搭自己的博客」，故不选 |

**结论：用静态站点生成器。**

**为什么静态方案对本项目是零损失**：静态站做不了的典型功能是评论与访问统计（都需要服务端存数据）——
而这两项已在 `需求与目标.md` 中被明确排除。**被砍掉的功能和做不了的功能恰好重合，所以不选动态方案没有任何代价。**

静态方案的附带好处：零服务器、零数据库、零运维、免费托管、无后台可被攻击、访问速度极快。

## 二、生成器候选对比

| 维度 | Hugo | Hexo | Astro |
|---|---|---|---|
| 安装 | 一个 exe | Node + 大量 npm 依赖 | Node + 大量 npm 依赖 |
| 写文章位置 | `content/posts/` | `source/_posts/` | `src/content/` |
| 模板语言 | Go 模板（`{{ range .Pages }}`） | EJS | HTML + JS/TS，接近普通网页 |
| 代码高亮 | 内置（Chroma） | 内置 | 内置（Shiki），观感更好 |
| 数学公式 | 需配置，新版稍绕 | 插件 | 装两个插件，配置几行 |
| 生成速度 | 极快 | 文章多了明显变慢 | 快 |
| frontmatter 写错时 | 常常**静默失败**（不报错，值就是不显示） | 一般不报错 | **会报错并指出出错行**（schema 校验） |
| 主题数量 | 多，技术博客主题成熟 | 多，中文主题丰富 | 较少，偏文档站 |
| 报错友好度 | 一般 | 一般 | 好（自带类型检查） |
| 改造时学到的知识 | Go 模板 —— **只在 Hugo 内可复用** | EJS —— 可迁移性低 | HTML/JS/组件 —— **前端通用** |

> **「静默失败」这一行值得单独留意**：新手最常见的错误是 frontmatter 写错（少引号、日期格式不对）。
> Hugo 通常不报错，只能看着页面上空白的位置猜原因；Astro 会直接指出哪一行有问题。
> 在学习阶段，这个差别的实际影响大于「生成速度」。

**Hexo 为何退出二选一**：它的核心优势是中文教程最多、卡住时能搜到答案。
但本项目有 AI 全程在场，用户不需要自己搜 —— 优势被抵消，而短板（依赖多、构建慢）仍在。

## 四、决定性差异

**在「只写文章 + 用现成主题」阶段，两者体验几乎无差别。** 真正的分叉发生在**要改造网站的那一天**：

| | 那时要学 | 学到的东西能迁移到哪 |
|---|---|---|
| **Hugo** | Go 模板语法 | **只在 Hugo 里用得上** |
| **Astro** | HTML / JS / 组件 | **前端到处都能用**（React、Vue 等一脉相承） |

这就是两者唯一真正需要权衡的地方：**Hugo 起步更快、故障更少；Astro 起步多花几分钟，但投入的时间能变成通用技能。**

## 五、待拍板

| 选项 | 选它，如果 | 代价 |
|---|---|---|
| **Hugo** | 目标就是「专心写技术文章」，希望工具尽量不干扰；不想在环境上多花时间 | 以后想深度定制时，学的 Go 模板不易迁移 |
| **Astro** | 想把博客当**练手项目**，顺便学一点前端；以后可能想扩成个人网站（作品集、项目页等） | 起步需先理顺 Node/npm 环境（约几分钟）；依赖多一层不确定性 |

> **两者不是一次定终身的。** 文章内容都是 Markdown，换工具时**文章能原样带走**，
> 但主题配置与 URL 结构需要重做。所以切换成本 = 「配置重做」，不是「内容重写」。
> 结论：可以放心先选一个用起来 —— 但**别抱着"反正能换"的心态随便选**，配置重做的坑是真实存在的。

## 六、已排除方案（存档理由）

| 方案 | 排除理由 |
|---|---|
| WordPress 等动态博客 | 需服务器 + 数据库 + 运维，违背「不做后台」「不自己运维」 |
| 自己写前后端 | 会把项目变成「只做站不写文章」，违背成功标准第 5 条 |
| 知乎 / 掘金 / CSDN 等平台 | 内容不归自己、样式不能改，与「搭自己的博客」目标不符 |
| Hexo | 核心优势（中文资料多）被「AI 全程在场」抵消，短板仍在 |
| Jekyll | Ruby 环境在 Windows 上是出了名的难装，与本项目「少出故障」的要求相悖 |
