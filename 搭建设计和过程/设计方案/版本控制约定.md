# 版本控制约定（Git）

> 状态：已启用（2026-09-19）

## 为什么用 Git

Git 和 `CHANGELOG.md` **不是替代关系，是互补**：

| 维度 | Git | CHANGELOG.md |
|---|---|---|
| 记什么 | 改了哪些文件、逐行差异 | 为什么改、当时怎么想 |
| 谁来写 | 工具自动生成，不用手写 | 需要人 / AI 用文字总结 |
| 精度 | 行级，**不会漏** | 靠自觉，**可能漏** |
| 可读性 | 要会看 diff | 大白话，一眼懂 |
| 能否篡改 | 改历史要留痕 | 改了没人知道 |

**关键好处：Git 是兜底。** CHANGELOG 漏记了，`git status` / `git diff` 立刻能看出哪些文件变了，能补回来。这解决了「自动记录其实不完全自动」那个硬伤。

## 仓库位置

`D:\file\myblogweb`（项目根目录），**代码和文档一起管**，主分支 `main`。

## 已做的配置

| 配置项 | 值 | 作用 |
|---|---|---|
| `core.quotepath` | `false` | 中文文件名正常显示，不显示成 `\346\226\207` 这种乱码 |
| `core.autocrlf` | `true` | Windows 换行符自动转换，仓库内统一用 LF |

## 哪些东西不进仓库

| 忽略项 | 原因 |
|---|---|
| `.workbuddy/` | AI 的记忆数据，不是博客内容。避免以后仓库公开时把私人笔记一起发出去 |
| `node_modules/`、`dist/`、`.cache/` | 依赖和构建产物，体积大且能重新生成 |
| `.env`、`*.key`、`*.pem` | 密钥密码，**绝对不能提交** |
| `Thumbs.db`、`.DS_Store`、`*.log` | 系统垃圾和日志 |

完整规则见根目录 `.gitignore`，里面每条都有中文注释。

## 提交信息规范

格式：**`类型: 一句话描述`**

类型固定 5 个词，**和 CHANGELOG 完全一致**：

| 类型 | 什么时候用 |
|---|---|
| 新增 | 加了新文件 / 新功能 |
| 修改 | 改了已有内容 |
| 删除 | 删掉文件或功能 |
| 重构 | 结构大改，功能不变 |
| 样式 | 只改外观、配色、排版 |

示例：

```
新增: 首页骨架
修改: 导航栏配色改浅
样式: 文章卡片圆角调到 8px
```

需要解释「为什么」时，空一行再写正文：

```
修改: 导航栏配色改浅

原色在深色屏上对比度不够，看起来发灰。
```

## 日常怎么用

**你不需要敲任何命令。**

每次改动完成后我自动提交，按上面的规范写提交信息，同时往 `CHANGELOG.md` 追加一行并回填本次提交号。

唯一的例外：如果你**自己手动改了文件**，跟我说一声改了啥就行，我会先 `git status` 对比出真实差异，再补记和提交 —— 不靠你描述，靠 git 看事实。

## 和 CHANGELOG 的联动

`CHANGELOG.md` 表格最后一列是本次改动对应的提交号（短 hash，如 `4b860ff`）。

- 想知道某次改动具体动了哪些行 → `git show 4b860ff`
- 从一行代码反查当时为什么改 → 在 CHANGELOG 里搜这个号

两个方向都能走通，这是这套结构最实用的地方。

**提交号怎么填：** 提交号得提交完才知道，填不进正在提交的那个文件里。所以规则是 —— 写新条目时顺手回填上一条，最新那条暂时标 `——`；每次收工前补全。

**纯记账性提交不单独占行**（比如回填提交号、改错别字），否则会无限套娃。

## 想自己看一眼历史（可选）

```bash
git log --oneline          # 一行一条，看全部提交
git status                 # 看当前有哪些改动还没提交
git show 4b860ff           # 看某次提交的具体改动
```

## 备份策略

### 远程仓库：暂不接（2026-09-19 决定）

现阶段只在本地建仓库，不接 GitHub / Gitee。

**代价要讲清楚：本地 git 只防「改错了想回退」，防不了硬盘坏掉。** 目前整个仓库只有一份物理副本，这块盘挂了就全没了 —— github 上不会有一份。

**退而求其次的做法（成本最低）：** 定期把整个 `D:\file\myblogweb` 文件夹复制到另一块盘或移动硬盘。纯文本文档很小，复制起来很快。别只存在同一块盘的不同文件夹里 —— 那不叫备份。

**什么时候该回头接远程仓库：**

| 触发条件 | 原因 |
|---|---|
| 博客要上线部署 | 主流免费托管都靠远程仓库自动部署 |
| 想换台电脑 / 用手机接着写 | 远程仓库是天然的同步点 |
| 硬盘只剩一块、没有备份盘 | 这是最后一道保险 |

只改文档、纯本地练习的话，可以一直不接。
