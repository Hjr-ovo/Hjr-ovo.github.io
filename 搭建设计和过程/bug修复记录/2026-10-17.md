# 2026-10-17 bug 修复记录

## BUG-015 Vite 改写动态 import 留下未定义占位符 `__VITE_PRELOAD__`，搜索永远提示「索引未生成」

- 发现时间：2026-10-17 11:40
- 现象：搜索页渲染正常、输入框能按 `?q=` 自动填词，但状态栏一直显示
  「搜索索引还没生成：这个功能要在构建后的站点里用」。页面无可见报错。
  可 `/pagefind/pagefind.js` 用 curl 访问明明是 **200**，文件也好端端躺在 `dist/` 里。
- 复现步骤：
  1. 页内写 `import(/* @vite-ignore */ '/pagefind/pagefind.js')`
  2. `npm run build`（构建产物里带 PageFind 索引）
  3. 打开 `dist` 站点的 `/search/?q=npm`
- 报错信息：产物 JS 里出现
  `r(()=>import('/pagefind/pagefind.js'), __VITE_PRELOAD__)`，
  而 `__VITE_PRELOAD__` **全文只出现这一次、从未定义** →
  运行时 `ReferenceError: __VITE_PRELOAD__ is not defined`。
- 定位过程：先排除路径与服务端（curl 200）→ 再怀疑 PageFind 模块格式 →
  最后直接打开 `dist/search/index.html` 看产物，发现 import 被套了预加载包装且占位符未替换。
- 根因：Vite 会把动态 import 自动包进 `__vitePreload(...)` 预加载辅助函数；
  `@vite-ignore` 只阻止「把路径当模块解析」，**没阻止「套预加载包装」**；
  而在这条内联 script 的产物里，占位符 `__VITE_PRELOAD__` 没有被替换成实际依赖列表。
- 修复：用 `new Function('url', 'return import(url)')` 把 import 藏进字符串里。
  打包器静态分析看不见，产物原样保留 `import('/pagefind/pagefind.js')`。
- 涉及文件：`site/src/pages/search.astro`
- 验证：① 产物中 `__VITE_PRELOAD__` 数量归零；② 浏览器打开 `/search/?q=npm`
  显示「找到 2 篇相关文章」且命中词高亮；③ 刷新后 `?q=` 仍生效。
- 反思：**「功能没反应」先看构建产物，别只盯着源码。** 源码里 import 写得再对，
  过一遍打包器就可能不是那个东西了。另外 **catch 里别把错误完全吞掉** ——
  当时哪怕 `console.error` 一行，ReferenceError 立刻就能看见，不用绕这么大圈。
- 状态：已修复
