# 博客管理工具 · 使用说明

> 这份是**给自己看**的操作手册。设计思路见同目录 `技术架构.md`。
>
> 状态：**已可用（2026-09-20 实测通过）**

---

## 一、怎么启动

**双击 `启动.bat`** 就行了。

会发生这些事：

1. 弹出一个黑色命令行窗口，**几秒后它会自己关掉**
2. 工具在后台跑起来，自动打开浏览器到 `http://127.0.0.1:5678`
3. 你看到的是「博客管理工具」的界面

> **想关闭工具，点界面右上角的「关闭工具」按钮。**
> 放心，**博客不受影响** —— 它是另一个进程。

---

## 二、几个按钮干什么

### 「打开博客」/ 「关闭博客」（右上角，同一个位置）

这是**一个按钮，两种形态** —— 位置不动，字和颜色随博客状态变：

| 博客状态 | 按钮长什么样 | 点下去会怎样 |
|---|---|---|
| 没在跑 | 蓝色实心「**打开博客**」 | 自动启动博客，然后打开 `localhost:4321` |
| 正在跑 | 红色描边「**关闭博客**」 | 问你一句，确认后把博客关掉 |

旁边的小标签会同步显示 `博客未启动` 或 `博客运行中 :4321`。

**关闭是这么做的**（先温柔、超时再强杀）：

1. 先请 Astro 自己退出，最多等 5 秒
2. 5 秒还没退，就强制结束

这样 Astro 有机会自己清理临时文件。关完会顺手清掉进程号记录。

> **为什么本地要能关博客**：不需要一直挂着它占电脑资源，要用的时候再开就行。
> 关博客**不影响管理工具**，关管理工具也**不影响博客** —— 两个独立进程。

#### 关闭时的安全设计

关的时候工具会**先认准"这是我们的博客"**，认不出就不动手：

| 情况 | 工具怎么做 |
|---|---|
| 启动时记了进程号 | 只用那个进程号去关（最准） |
| 进程号记录丢了 | 按命令行找"跑着 astro、且是我们的站点目录"的进程 |
| 两者都找不到 | **不关**，告诉你去任务管理器手动处理 |

> 这是为了避免误杀 —— 万一 4321 端口被别的程序占了，工具**不会**看着"端口被占"就乱杀。

### 「＋ 新建文章」

点进去填表单：标题、摘要、日期、分类、标签，然后写正文。

**文件名那栏要特别注意** —— 点「从标题生成」可以让工具给个候选英文名，
但**建议自己看一眼改改**。理由：文件名会变成文章 URL 的一部分，
而"哪几个词是别人会搜的"，只有你自己知道。

### 「编辑」

点开某篇文章改。改完点保存。

**保存时工具会自动把「更新日期」设成今天** —— 你的需求里说技术内容要标更新时间，这个是自动的。

**改标题时会问你一句要不要顺便改文件名**（默认选"不改"）。
详见下面第四节。

### 「删除」

点了会弹确认框，然后：

1. 先把这篇文章复制到备份目录
2. 确认备份成功**才**删原文件
3. 告诉你备份在哪

**删错了怎么找回**：去 `D:\file\myblogweb\.workbuddy\tmp\deleted-posts\`
把那个文件复制回 `site\src\content\posts\` 就行。备份文件名带时间戳，好认。

## 三、两种写正文的方式

### 方式 1：直接在工具里写

编辑页有个大文本框，直接写 Markdown。

**快捷键**：

| 按键 | 作用 |
|---|---|
| `Ctrl + S` | 保存（不用去点按钮） |
| `Esc` | 关弹窗 |

### 方式 2：从 Obsidian 导入

点「从文件导入正文…」，选你在 Obsidian 里写好的 `.md` 文件。

**会做的事**：如果那个文件自带 frontmatter，工具**只取正文部分**，
不会和工具生成的 frontmatter 打架。

**如果文本框里已经有内容**，会问你：替换，还是追加到后面。

## 四、改标题和改文件名（**这条容易踩坑，仔细看**）

### 为什么分成两件事

| | 改标题 | 改文件名 |
|---|---|---|
| 影响 | 文章显示的名字 | **文章 URL** |
| 后果 | 看到的人知道就行 | 旧链接会失效 |

工具的规矩是：**改文件名必须是你的明确决定，绝不能悄悄发生。**

### 实际流程

```text
你改了标题 → 点保存 → 工具问：「标题变了，要不要顺便改文件名？」
                              ↓
                    默认按钮是「不改，只改标题」
                              ↓
            点「顺便改成新的」→ 工具再给个候选名让你确认
```

### 什么时候该改文件名

- ✅ 文章写歪了，方向变了，URL 里的旧词完全不搭
- ❌ 只是润色了一下标题的措辞

**理由**：博客**上线之后**，改文件名会让别人收藏的链接、外站的引用全部 404。

> 现在还没上线，所以改了也没人受影响。
> 但**别养成习惯** —— 上线后某次随手改标题就会制造死链。
> 工具还会再问你，这是故意的。

### 「URL 自动定位」（旧链接不失效）为什么现在没做

能做，叫**重定向**，但**现在做是白做**：

> 需求文档里写着「**第 3 类读者当前数量为 0**（博客还没上线）」

没人访问过 = 没人收藏过任何链接 = **现在改 URL 的代价是 0**。
所以这个机制留到**上线时**再加，方案已经存档在 `技术架构.md` 的 5.5.2 节。

## 五、写文章时必须守的规矩

工具会帮你挡掉大部分错误，但有三条你要知道：

| 规矩 | 为什么 |
|---|---|
| **文件名只能用英文小写 + 数字 + 短横线** | 中文会变成百分号编码的 URL；大写在你电脑上能跑，传到 Linux 服务器就挂 |
| **日期必须 `YYYY-MM-DD`** | 格式错一个字，Astro 构建直接失败（这个工具会在保存前拦住你） |
| **标题、摘要、日期、分类必填** | 缺了构建会报错 |

工具**保存前会自查**，有问题会直接告诉你缺什么，不用等构建才发现。

## 六、关于「草稿」

编辑页有个「存为草稿」勾选框。

- 勾上 → **不出现在博客上**，只你自己在工具里看得到
- 不勾 → 正常显示

适合"写了一半先存着"。

## 七、常见问题

**Q：黑窗口报「没找到 Node.js」怎么办？**
A：打开 `启动.bat`，把 `NODE_EXE` 那行的路径改成你电脑上 node.exe 的真实位置。
（用 `where node` 命令可以查，注意要排除 WorkBuddy 自带的那个。）

**Q：浏览器没自动打开？**
A：手动访问 `http://127.0.0.1:5678`。

**Q：双击后黑窗口一闪而过，什么都没发生？**
A：这个故障 2026-09-20 修过一次（BUG-008），原因是 `启动.bat` 的**行尾是 LF 而不是 Windows 的 CRLF**，
再叠加**中文注释**被命令行当成命令执行。修好后的文件不会再出现，但如果你**自己编辑过这个 .bat 并另存**，
可能又把它存成了 LF 行尾 —— 那时用记事本打开、另存为时选「ANSI」或保持原样即可，别改行尾。
判断方法：把 `启动.bat` 拖进命令行窗口跑一次，报错就会留在屏幕上不会一闪而过。

**Q：点了「打开博客」但页面打不开？**
A：看工具给的提示。最常见的原因是 Astro 依赖没装 —— 去 `site` 目录跑一次
`"C:\Program Files\nodejs\npm.cmd" install --ignore-scripts`。

**Q：工具里改了文章，博客页面没变？**
A：Astro 有热更新，通常一两秒就变。没变就刷新一下浏览器。

**Q：能同时在 Obsidian 里改站点文件吗？**
A：可以。工具**每次都重新读磁盘**，不缓存内容，所以你改的它能看到。

**Q：图片怎么办？**
A：工具**不管图片**。因为你的 Obsidian 插件在粘贴时已经把图片换成网络链接了，
工具只需要原样搬运文字。

## 八、工具的边界（别指望它做的事）

| 不做 | 为什么 |
|---|---|
| ❌ 不是网站后台 | 博客是静态站，没有服务器，不存在"网页点发布就上线" |
| ❌ 不装主题、不改站点代码 | 耦合越浅越好 —— 工具坏了，网站照样跑 |
| ❌ 不做批量删除 | "一次点错"的代价会从 1 篇变成 N 篇 |
| ❌ 不管图片上传 | 走你现有的 PicGo 图床流程 |
| ❌ 不自动改文件名 | 见第四节 |
| ❌ 不做撤销删除的按钮 | 备份只是兜底，恢复靠手动拷回来 |

## 九、这个工具改动了什么文件

放在 `博客管理工具/` 里，各文件干什么：

| 文件 | 作用 |
|---|---|
| `启动.bat` | **双击这个启动** |
| `技术架构.md` | 设计文档（为什么这么设计） |
| `使用说明.md` | 就是本文 |
| `src/config.mjs` | 路径与端口配置（**换电脑只改这里**） |
| `src/frontmatter.mjs` | frontmatter 解析与拼装（**最要紧的文件**） |
| `src/posts.mjs` | 文章的读 / 写 / 删（含删除备份） |
| `src/slug.mjs` | 中文标题 → 英文文件名 |
| `src/blog-server.mjs` | 启动博客、检测端口 |
| `src/server.mjs` | 后端服务与接口 |
| `public/index.html` | 界面骨架 |
| `public/style.css` | 界面样式 |
| `public/app.js` | 界面逻辑 |

**它只会动这两个地方**：

- `site/src/content/posts/*.md` —— 你的文章
- `.workbuddy/tmp/deleted-posts/` —— 删除的备份

## 十、实测记录（2026-09-20）

写完之后跑了三套测试，都过了：

| 测试 | 覆盖 | 结果 |
|---|---|---|
| 核心逻辑自测 | frontmatter 解析/拼装、日期校验、文件名生成、转义 | **54 / 54** |
| 接口端到端 | 12 组接口（增删改查、校验拦截、路径穿越防护、删除备份） | **46 / 46** |
| 完整链路 | 用工具发文 → 去博客页面确认真的出现 → 改 → 设草稿 → 删 | **19 / 19** |

**其中验证到的关键点**：

- 标题含引号、冒号、`#` 都能正确往返（frontmatter 不会写坏）
- 错误日期格式被拦下，并说明格式要求
- 重名时拒绝创建，**不会覆盖**已有文章
- 删除确实产生了可复原的备份（实测 6 次，内容完整）
- 设为草稿后博客首页确实看不到了
- 删除后文章详情页确实返回 404

**过程中修掉的两个真 bug**（已记入 `bug修复记录`）：

1. **frontmatter 反斜杠越存越多** —— 拼装时转义了 `\"`，解析时没反转义
2. **误报"博客启动失败"** —— Astro 只绑 IPv6 的 `::1`，而检测时只查了 IPv4 的 `127.0.0.1`，
   导致博客明明 2 秒就绪，工具却白等 60 秒然后报错
