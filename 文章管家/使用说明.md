# 文章管家 · 使用说明

> 本地小工具，用来**发文**和**改元数据**。不是后台，不能上线后用（GitHub Pages 跑不了 Node）。
> 双击根目录的 `文章管家.bat` 打开，关掉那个黑窗口就停。

---

## 一、它能干什么

| 页面 | 干什么 |
|---|---|
| **文章** | 看站里有什么、搜索、按分类筛、看字数和阅读时长；点标题进编辑 |
| **入库** | 把 Obsidian 写的 `.md` 拖进去 → 工具告诉你「这篇会发生什么」→ 起个英文名、选分类 → 写进站点 |
| （编辑页） | 改标题/摘要/日期/分类/标签、开关草稿、修正文错别字 |

**只有这三件事。** 不做富文本写文章、不做预览、不做图片上传、不做发布上线 —— 原因写在
`搭建设计和过程/设计方案/后台工具设计.md` 第十节。

---

## 二、入库：从 Obsidian 到站点

1. 双击 `文章管家.bat`
2. 点左边「入库」
3. 把 `.md` 拖进虚线框（或点一下选文件）
4. **先看左边那列诊断**，它会告诉你：
   - 缺不缺必填字段（缺 `description` 构建立刻失败）
   - 有没有标题跳级（`#` 后面直接 `####`，目录收不到）
   - 有没有本地图片路径（站点上会裂，这是这类工具第一大坑）
   - 几处 `==高亮==` 会转换、代码块里的 `==` 会不会被误伤
   - 分类是不是新的（会新建一个分类页）
5. 右边确认/修改：文件名（= URL）、标题、摘要、日期、分类、标签
6. 点「写入站点」

**诊断只预测，不写文件。** 真实效果以站点渲染为准。

**文件名规则**：只能英文小写、数字、短横线。因为文件名就是 URL，
中文会变成 `%E5%93%88%E5%B8%8C` 这种编码，分享出去很难看。

**写入之后，这条稿子的「正本」就变成站点里那一份了。** Obsidian 里的原件留着当底稿，
但以后要改请改站点这份 —— 否则两边会分叉。

## 三、编辑：改的是什么

上半是元数据表单，下半是正文。

三条规矩（也是这个工具存在的理由）：

| 规矩 | 你会看到什么 |
|---|---|
| **只改你动过的那几行** | 改一个标签保存后，`git diff` 里就只有 `tags:` 那一行变。注释、空行、字段顺序、引号风格，全都不碰 |
| **正文不做任何格式化** | 不 trim、不补末尾换行、不转全角半角。改一个错字，diff 就只有那一行 |
| **绝不静默覆盖** | 保存前会重新读磁盘。文件在别处被改过（比如你又用 Obsidian 动了一下），会弹框问你要覆盖还是放弃 |

`Ctrl+S` 也能保存。有未保存改动时，关页面会拦你一下。

顶部「在站点打开」会跳到 `localhost:4321` 对应的文章页；站点没开着就提示你先双击 `预览.bat`。

## 四、没做的功能（别找了）

| 想做的事 | 现在怎么做 |
|---|---|
| 改文件名（= 换 URL） | 手动改文件名 + 往 `site/src/data/redirects.json` 加一条跳转（ADR-011） |
| 删文章 | 直接删 `site/src/content/posts/` 里的文件（git 可以找回） |
| 看哪个分类有几篇 | 点顶部的「全部分类」下拉，或看站点的分类页 |
| 看有没有坏链、错字段 | 目前没有全站体检；单篇的问题在入库诊断里能看到 |
| 提交 git | 手动 `git add` / `git commit`（这个工具不碰 git） |

这些都在设计文档里排了优先级，真觉得缺再加 —— 加功能是加页面，不用重写。

## 五、文件在哪

| 东西 | 位置 |
|---|---|
| 工具本体 | `文章管家/`（`src/` 是后端，`public/` 是界面） |
| 启动 | 根目录 `文章管家.bat` |
| 它唯一会写的地方 | `site/src/content/posts/*.md` |
| 端口 | `127.0.0.1:5678`（只本机可访问，没有登录） |

站点其它文件（样式、组件、配置）它一律不碰。

---

## 六、出问题怎么办

| 现象 | 原因 / 处理 |
|---|---|
| 浏览器显示「无法访问」 | 黑窗口关掉了。重新双击 `文章管家.bat` |
| 提示「端口 5678 被占用」 | 已经开着一个了，直接打开 `http://127.0.0.1:5678/` |
| 顶部「站点未运行」 | 博客预览没开。双击根目录 `预览.bat` |
| 保存时弹「磁盘上的文件更新了」 | 你在 Obsidian 或别处又改了这篇。选「取消」然后点「重新从磁盘读」 |
| 入库提示「已经有一篇叫 xxx.md 的文章」 | 换个文件名，工具不会自动加 `-1`（两个名字长得像会更乱） |

## 七、技术上的两个取舍（免得以后好奇）

**为什么不用现成的 Keystatic / Decap CMS？**
它们要么需要 GitHub OAuth（要服务器、要登录），要么用 Markdoc 存正文 —— 后者会重写你的
`==高亮==` 和 `cpp+tab` 代码块，而我们对正文的要求是「一个字节都不动」。
详见 `搭建设计和过程/设计方案/后台工具调研.md`。

**为什么零依赖、不用框架？**
这个仓库装 npm 包踩过 23 分钟无输出的坑（BUG-002）。全部用 Node 内置模块 + 原生
HTML/CSS/JS，没有 `node_modules`，也就没有「半年后跑不起来」的风险。
