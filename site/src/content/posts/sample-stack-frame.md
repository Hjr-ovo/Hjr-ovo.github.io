## 环境

- x86-64 架构，System V ABI
- 编译器不做激进的尾调用优化

## 一次调用的现场

看这段最普通的代码：

```c
int add(int a, int b) {
    int sum = a + b;
    return sum;
}

int main(void) {
    int r = add(1, 2);
    return 0;
}
```

调用 `add` 时，系统要保证三件事：

1. 被调函数执行完能**回到正确的位置**
2. 回到 `main` 之后，`main` 的局部变量**还在原样**
3. 参数能被 `add` 读到

这些信息全都放在**栈**上，合起来叫一个**栈帧**。

## 栈帧里有什么

| 内容 | 作用 |
|---|---|
| 返回地址 | 函数结束后跳回哪里 |
| 调用者的栈基址 | 恢复调用者的栈现场 |
| 保存的寄存器 | 调用者正在用的寄存器不能被破坏 |
| 局部变量 | 本函数的自动变量 |
| 参数（部分） | 寄存器放不下的部分 |

## 为什么栈要「向下增长」

x86-64 上栈从高地址往低地址长，这是历史选择。带来的实际影响：

```text
高地址
  ┌──────────────┐
  │  main 的栈帧  │
  ├──────────────┤
  │  add 的栈帧   │  ← 新帧在这个方向推进
  ├──────────────┤
  │   未使用空间   │
  └──────────────┘
低地址
```

好处是**读写操作都在同一端进行**，缓存局部性好。

## 递归为什么会栈溢出

每层递归都要**新建一个栈帧**，栈的总大小是固定的（Linux 默认约 8 MB）：

```c
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);   // 每层都要等下一层返回
}
```

`fact(100000)` 就会崩 —— 不是因为算得慢，而是**栈帧堆到超过了栈的界限**。

关键点：只有**尾递归**才能被优化掉栈帧（变成循环），
上面这种 `n * fact(n-1)` **不是尾递归**，因为乘法要在下一层返回之后才做。

## 一个反直觉的点

函数调用的开销**不只是「跳转」**。

真正的开销在于：

- 要把寄存器写进内存（保存现场）
- 要在返回时再读回来（恢复现场）
- 参数多的函数还要走栈传参

所以「多写几个小函数」并不总是免费的 —— 这也是为什么内联优化对性能影响那么大。

## 小结

1. 栈帧 = 返回地址 + 保存的现场 + 局部变量 + 参数
2. 每层递归一个栈帧，栈大小固定 → 太深就溢出
3. 只有尾递归能省掉栈帧，形似递归的写法往往不是尾递归
